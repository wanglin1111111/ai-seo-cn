# 渠道测量协议（Channel Research Protocol）

> 目的：把渠道映射表里「假设待测」的行升级成「实测」行。**测量是唯一升级路径**——没有留档的偏好，不管写得多像真的，都是「假设待测」。

## 一、为什么必须测量（不测量的后果）

```
中文 AI 渠道的引用逻辑没有公开文档（各平台不披露引用权重/源池细节），
所有"DeepSeek 偏好 FAQ 块"这类结论的来源只有两种：
  1. 实测（自己跑问题、看答案、归纳被引用内容的共性）
  2. 转述（某篇文章/某次分享说的——不可验证，等价于「假设待测」）
把转述当实测的后果：优化动作建立在不可验证的偏好上，
  复测时出现率不升，归因时无法区分"偏好错了"还是"内容没做好"——
  因为"偏好"从一开始就没有证据。
```

## 二、测量单元：固定 5 问题 × 每渠道 5 次

### 问题集设计（测前定死，测中不改）

```
5 个问题的构成（与 ai-visibility-audit-cn.md 的审计问题同构）：
  Q1 品类词：「<你的品类> 有哪些好用的工具/方法？」
  Q2 对比词：「<你的产品> 和 <直接竞品> 哪个好？」
  Q3 场景词：「<典型使用场景> 应该怎么解决？」
  Q4 竞品词：「<竞品> 怎么样？有什么缺点？」（看渠道引用谁的内容来评价竞品——
    你的内容若被引用来对比，说明已进入该渠道的"评价源池"）
  Q5 长尾痛点：「<具体痛点，含数字/条件> 怎么办？」
  （具体措辞从 product-marketing.md 的目标 query 里选，选完写进留档，
   复测必须用同一组措辞——问题表述漂移 = 数据作废）
设计判据：
  [ ] 5 个问题的答案"理想状态"都包含你的产品/品牌实体（否则该问题测不出你的可见性）
  [ ] 问题用用户真实会问的口吻（不用"请推荐 X 类工具"这种机器腔——
     用户问法和机器问法的引用行为可能不同，测用户问法）
  [ ] 5 个问题测前全部写进留档（文件里固定下来，不是每次现想）
```

### 每渠道 5 次的执行

```
同一问题连续问 5 次（间隔几秒即可，不刻意改措辞），记录每次：
  第 n 次 | 渠道 | 问题编号 | 是否出现品牌实体(是/否)
          | 引用的来源(域名/文章标题，没有写"无引用")
          | 引用内容的结构特征(长文段落/FAQ块/列表/表格——看被引内容原文的结构)
          | 原始答案留档(截图或文本，存 <留档目录>/<渠道>/<日期>/Q<n>-<n次>.md)
为什么 5 次：AI 回答有随机性，单次出现可能是偶然；5 次给一个粗略的
  稳定性信号（5/5 出现=稳定；1-2/5=不稳定；0/5=未出现）
留档目录结构（强制）：
  .agents/ai-seo-cn-evidence/
    <渠道名>/<测量日期>/
      questions.md        ← 本次用的 5 个问题（原样）
      Q1-1.md … Q5-5.md   ← 30 次回答的留档（每文件：问题+答案原文+来源+结构特征）
      summary.md          ← 归纳（引用率/结构共性/来源池观察）
没有 questions.md + 30 个回答文件 = 这次测量不算数（「实测」资格不成立）
```

## 三、结构偏好的归纳方法（从被引内容反推，不靠猜）

```
归纳的输入：30 次回答里"被引用的内容"的原文（不是你的猜测，是引用发生处的原文）
归纳三步：
  1. 结构标注：每个被引片段标结构（长文段落 / FAQ 块 / 有序列表 / 表格 / 小标题+短段）
     注意：标的是"被引用片段本身的结构"，不是"该页面整体的结构"
  2. 频次统计：5 类结构各被引多少次（按该渠道 30 次回答汇总）
  3. 结论写法（进映射表"结构偏好"列）：
     实测句式：「<渠道> 30 次回答中引用片段结构：FAQ 块 12 次 / 小标题+短段 9 次 /
     列表 6 次 / 长文 3 次 / 表格 0 次（2026-MM-DD 留档 <路径>）」
     ——必须带次数和留档路径，否则格式不合格，该行不算「实测」
禁止的归纳（常见错误）：
  ✗ 从"我的内容在哪个渠道表现好"反推偏好（表现好可能是实体密度/时效/源池，
     不一定是结构——混淆归因）
  ✗ 一次测量（5 次/问题）就下"偏好"结论（样本 25 次，只够报"观察"，
     够不上"偏好"；两次测量（10 次/问题）结论一致才可写"偏好"，不一致写"不稳定"）
  ✗ 把"该渠道引用了我的内容"当成"该渠道偏好这种结构"（引用≠偏好，
     引用可能只因为源池里只有你——先查该渠道引用池的多样性）
```

## 四、「假设待测」→「实测」的升级判定

```
升级条件（全部满足，缺一不升）：
  [ ] 完成一次完整测量（5 问题 × 5 次 × 留档齐全：questions.md + 30 回答 + summary.md）
  [ ] summary.md 里的结论按"实测句式"写（带次数+留档路径）
  [ ] 映射表该行：状态改「实测」+ 数据来源填留档路径 + 日期填测量日期
  [ ] 结论仅限本次测量的观察范围（写"2026-MM-DD 测量中 FAQ 块被引最多"，
     不写"该渠道偏好 FAQ"——偏好是跨时间结论，需要两次测量一致才允许写）
降级条件（任何一条触发，「实测」降回「假设待测」）：
  留档丢失 / 复测结论与「实测」行矛盾（保留两版留档，行内标注"结论冲突，待三次测量"）
  / 该渠道重大更新（平台公告/明显行为变化）——重测前按「假设待测」对待
```

## 五、常见测量误差（测前知道，测后排查）

| 误差 | 症状 | 处置 |
|---|---|---|
| 同渠道不同入口结果不同 | App 与 Web/不同版本答案差异大 | 固定入口（留档里写清用哪个入口）；入口变了数据作废重测 |
| 问题表述漂移 | 第 3 次的问题和第 1 次措辞不同 | 每次粘贴 questions.md 里的原句，不改一字 |
| 回答含"我不知道"式拒答 | 引用 0 次但答案存在 | 拒答按"未引用"记录，但在 summary 里单列"拒答 n 次"（拒答率本身是信号：该渠道对这个 query 域没把握） |
| 引用来源无法定位 | 答案有观点但查不到来源文章 | 记"来源不明"，不猜；该数据点不能用于结构归纳 |
| 时间混淆 | 今天测的偏好和上个月的可能不同 | 每次测量独立留档带日期；映射表只保留最近两次测量的结论，更早的归档 |

## 六、测量排期（资源有限时先测谁）

```
优先级（按业务加权，不按好奇心）：
  P0 你的用户实际在哪个渠道问 AI（product-marketing.md 的受众场景定）
     ——用户不在的渠道测了也没用
  P1 P0 渠道里出现率最差的（差=优化空间大）
  P2 其余（有余力再测）
最小启动集：1 个 P0 渠道 × 1 次完整测量（5×5=25 次回答，约 2-3 小时含归纳）
  ——最小启动集跑完才谈"渠道矩阵"；一次铺 5 个渠道 = 每个都浅、都归不了因
```
