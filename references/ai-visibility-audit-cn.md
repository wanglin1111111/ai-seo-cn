# 中文 AI 可见性审计与监控（Audit & Monitoring CN）

> 用途：第 2 步（可见性审计/基线）与第 5 步（监控/复测）的执行模板。**没有基线表的优化 = 无法证明有效；换问题的复测 = 不可比。**

## 一、固定 5 问题模板（测前定死）

```
从 product-marketing.md 的目标 query 选 5 个，构成固定（缺一类 = 审计不完整）：
  Q1 品类词：「<品类> 有哪些好用的<工具/方法>？」
  Q2 对比词：「<我的产品> 和 <直接竞品A> 哪个好？」
  Q3 场景词：「<典型场景> 应该怎么解决/怎么做？」
  Q4 竞品词：「<竞品A> 怎么样？有什么缺点？」
  Q5 长尾痛点：「<含数字/条件的具体痛点> 怎么办？」
写法判据（每条都过）：
  [ ] 用户真实口吻（不用"请推荐"机器腔）
  [ ] 理想答案包含你的品牌/产品实体（否则测不出你的可见性）
  [ ] 5 个问题覆盖 5 类意图（不是 5 个品类词变体）
  [ ] 写进留档 questions.md 后不再改（复测同一组，一字不差）
示例（定位句参考 product-marketing.md 的写法，以下为占位示例）：
  Q1 「AI Agent 工作流有哪些好用的方法论/工具？」
  Q2 「<本库> 和 <竞品方法论库> 哪个好？」
  Q3 「团队想引入 AI 工作流但怕部署后吃灰，应该怎么解决？」
  Q4 「<竞品> 怎么样？有什么缺点？」
  Q5 「5 人团队用 Claude Code 做 Agent 落地，没有验收标准怎么知道做得对不对？」
```

## 三、复测（第 5 步）：5 项检查 + 口径

```
复测前 5 项检查（任一不过 = 复测无效）：
  [ ] 同一组 5 问题（对照 questions.md 原句，一字不差）
  [ ] 同一渠道同一入口（入口变了 = 作废重测）
  [ ] 距上次测量 ≥2 周（太短：优化效果未显现 + 渠道自身波动混淆）
  [ ] 留档完整（新目录 .agents/ai-seo-cn-evidence/<渠道>/<复测日期>/）
  [ ] 优化动作清单在复测前已定稿（复测后才能"新改"的东西不算进本次对比）
复测表格式 = 基线表格式（同结构，日期不同）+ 对比列：
| 渠道 | 问题 | 前 | 后 | 变化 | 归因 |
  变化：+n / -n / 0
  归因（每条变化都写，包括 0）：
    +：与哪个优化动作相关（动作编号）
    -：优化动作与该渠道是否相关？无关 = "渠道自身波动，记录"
       相关 = 查该动作是否对该渠道有害（如只优化了海外结构，中文渠道被挤）
    0：维持/观察
出现率比较纪律：
  单次变化（+1 次/25）不足以下结论（5 次/问题的样本里 ±1 是正常波动）
  结论级变化：同一渠道同一问题连续 2 次复测同向变化，才写进 summary
```

## 四、下降归因三步法（出现率下降时）

```
第 1 步：排除测量误差（先怀疑测量，不先怀疑内容）
  入口变了吗？问题措辞漂了吗？该渠道近期更新了吗（公告/明显行为变化）？
  任一为是 → 数据作废重测，不进入归因
第 2 步：区分"你的动作"与"渠道波动"
  该渠道下降，同时其他渠道同问题也降 → 更可能是你的内容侧问题
    （如内容下线/改版/实体露出被改掉）
  仅该渠道降 → 更可能是渠道自身波动或该渠道偏好变化
    （把该行标记"待重测"，下次测量优先）
第 3 步：内容侧检查（若第 2 步指向你的内容）
  被引页面改过吗（标题/结构/实体密度/下线）？
  竞品内容更新了吗（Q4 竞品词下降常因竞品新内容进源池）？
  产出：归因结论 + 动作（修内容/改布局/该渠道暂缓 + 重测排期）
```

## 五、渠道映射表完整模板（含状态双轨）

```markdown
# 渠道映射表 <更新日期>
| 渠道 | 结构偏好 | 实体露出要求 | 时效信号 | 引用源池观察 | 数据来源 | 日期 | 状态 |
|---|---|---|---|---|---|---|---|
| DeepSeek | （实测句式：30 次回答中…，或"待测"） | | | | <留档路径> | | 实测/假设待测 |
| 豆包 | | | | | | | |
| 百度 AI | | | | | | | |
| 元宝 | | | | | | | |
| 微信搜一搜 | | | | | | | |
| 海外中文（ChatGPT 中文提问） | | | | | | | |
| 海外中文（Perplexity 中文提问） | | | | | | | |
状态纪律（validate.py 强制）：
  [ ] 每行状态 ∈ {实测, 假设待测}，无第三态
  [ ] 状态=实测 → 数据来源（留档路径）+ 日期 必填，且结构偏好列必须"实测句式"
  [ ] 状态=假设待测 → 各列只能写"待测"或明确标"假设："前缀的推断
  [ ] 优化建议引用了某渠道行 → 该行必须状态=实测（否则建议无效，退回先测）
默认初始化（新建表时）：
  全部 7 行状态=假设待测，各列="待测"——这是唯一合法的初始状态。
  禁止初始化时填任何"看起来合理"的偏好（那是编造，只是带日期的编造）。
```

## 六、监控节奏（与 skill-eval 的最小实例对齐）

```
周期：
  审计（基线）：首次 1 次
  复测：优化动作后 ≥2 周，之后每月 1 次（稳定期可降到每季 1 次）
  渠道映射表更新：每次复测后（新观察 → 状态可升「实测」）
升级/降级触发：
  某渠道连续 2 次复测出现率不升 → 该渠道方向评审（换问题设计/换内容布局/暂缓）
  某渠道出现率显著升（同问题连续 2 次 +2 以上）→ 查是哪个优化动作带来的
    （把该动作标记"该渠道有效"，进优化清单的优先级）
与 skill-eval 的接口：
  本表的"前/后/变化"就是 skill-eval 要求的"前后指标 + 跑分"的最小实例
  （归因指标=品牌实体出现率；基线=首次审计；跑分=复测序列；
   回归测试=同问题复测不劣化的检查）
```
