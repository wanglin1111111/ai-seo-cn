# ai-seo-cn 设计说明：为什么"测量协议"是第一步而不是附属品

## 背景

`skill-lib-iterate` L2-a 动作（AI 搜索本土化）的原始描述是：

> ai-seo 的引用源默认面向海外 AI，你要换成中文 AI 搜索渠道（元宝、DeepSeek、豆包、百度 AI、微信搜一搜）的内容结构偏好。

这句话隐含一个假设：**实施者已经知道中文渠道的"内容结构偏好"是什么**，只需要"换"。

## 执行中发现的真问题

落地这一步时发现该假设不成立：

1. **中文 AI 渠道的引用逻辑没有公开文档**。各平台不披露引用权重、源池构成、结构偏好——不存在一份可以"拿来替换"的中文渠道偏好表。
2. **所有现成的"渠道偏好"说法都是转述**。某篇文章说"DeepSeek 偏好 FAQ"、某次分享说"豆包偏长文"——这类说法不可验证，与未实测等价。把转述当实测的后果：优化动作建立在不可验证的偏好上，复测出现率不升时无法归因（分不清"偏好错了"还是"内容没做好"）。
3. **海外版 ai-seo 的上游语境不存在这个问题**。英文渠道有相对多的公开评测数据（Perplexity 的引用行为、ChatGPT 的搜索行为有第三方研究），机制推断的锚点更多。中文渠道连锚点都没有——所以"测量"从优化建议的附属品升级成了工作流的第一步。

## 设计决策：状态双轨

由此产生 ai-seo-cn 的第一护栏（诚实性总纪律）：

```
渠道引用偏好只有两种合法状态：
  实测    = 跑过测量协议 + 留档齐全（questions.md + 30 次回答 + summary.md）
            + 结论按实测句式写（带次数统计 + 留档路径 + 日期）
  假设待测 = 机制推断或未验证（输出时只能以"假设"身份出现，只能用于排期"先测什么"）
优化建议只能引用「实测」行。
渠道映射表的初始状态：全部 7 行 = 假设待测。这是唯一合法的初始状态——
禁止初始化时填任何"看起来合理"的偏好（那是编造，只是带日期的编造）。
```

这个设计把"我知道多少"从输出里显式化：读者看到的每个渠道结论都自带证据状态，
不存在"写得像真的但没测过"的中间态——因为中间态被格式禁止了
（validate.py D2 拦截第三态与无留档的 measured 行）。

## 测量协议的最小单元

```
固定 5 问题 × 每渠道 5 次 = 25 次回答/渠道（约 2-3 小时含归纳）
  5 问题：品类/对比/场景/竞品/长尾各 1（测前定死写进 questions.md，复测同一组）
  5 次：AI 回答有随机性，单次出现是偶然，5 次给粗略稳定性信号
结构偏好归纳：从"被引用片段的原文结构"反推（不靠猜）
  禁止：从"我的内容在哪表现好"反推（混淆归因）/ 一次测量下"偏好"结论
  （样本只够报"观察"，两次一致才写"偏好"）/ 引用=偏好（源池可能只有你）
```

## 与 skill-eval 的接口

ai-seo-cn 的监控节（基线审计→优化→复测）是 `skill-eval` 效果评估层在
"AI 可见性"场景的最小实例：

| skill-eval 要求 | ai-seo-cn 对应物 |
|---|---|
| 归因指标 | 品牌实体出现率（歧义命中单列，不计入） |
| 采用前基线 | 首次可见性审计表（优化前必须存在） |
| 跑分（≥2 周期） | 复测序列（间隔 ≥2 周） |
| 回归测试（关键要素稳定） | 同问题集复测 + 下降归因三步法 |
| 连续 2 周期不升→评审 | 同渠道连续 2 次复测不升→方向评审（换问题/换布局/暂缓） |

## 中文合规 veto（上游没有的硬差异）

英文语境的 ai-seo 不需要内置合规层（合规是发布环节的事）；中文语境把合规
前移进优化环节：内容在优化/发布前过 veto list（默认条目：广告法绝对化用语、
未标注的效果承诺、超行业许可的医疗/金融表述；行业追加条目各带出处）。
格式纪律与 marketingskills 的 newsjacking veto 一致：触发条件可判定 +
动作明确 + 带依据 + 写进机器可读配置（.agents/ai-seo-cn-veto.yaml）——
写进 README/文档/记忆的 veto 等于不存在（AI 每次生成前读不到）。
